## 🔌 Backend API Mapping

The frontend communicates with the backend `com.klef.soa.docker.controller.GymController` running on **port 8081**:

| Action | HTTP Method | Endpoint | Request Body | Description |
| :--- | :---: | :--- | :--- | :--- |
| **Health Check** | `GET` | `/gym/` | None | Checks if CrudService is running |
| **Get All Records** | `GET` | `/gym/Displayall` | None | Retrieves all equipment items |
| **Add Record** | `POST` | `/gym/Add` | `{ equipmentname, brand, purchaseCost, working }` | Creates new equipment (ID auto-assigned) |
| **Get by ID** | `GET` | `/gym/Get/{id}` | None | Fetches single equipment by ID |
| **Update Record** | `PUT` | `/gym/Update/{id}` | `{ equipmentname, brand, purchaseCost, working }` | Updates existing equipment |
| **Delete Record** | `DELETE` | `/gym/Delete/{id}` | None | Deletes equipment by ID |

## 🚀 How to Run the Frontend

You can run the frontend in any of the following simple ways:

### Option 1: Direct Browser Launch
Simply double-click or open `f:\soalab\frontend\index.html` in any modern web browser (Google Chrome, Microsoft Edge, Firefox).

### Option 2: Using VS Code / IDE Live Server
Right-click `index.html` in your editor and select **"Open with Live Server"**.

### Option 3: Using Node / Python Local Server
Run in PowerShell:
```powershell
# Using Python
cd f:\soalab\frontend
python -m http.server 3000

# Open in browser: http://localhost:3000
```

## 🧪 Full-Stack Integration & Testing Guide

### 1. Verification of Backend API via Swagger UI
- Start the Spring Boot backend (`CrudServiceApplication` on port `8081`).
- Open Swagger UI in your browser:
  **`http://localhost:8081/swagger-ui/index.html`**
- Test the endpoints directly in Swagger UI:
  - `GET /gym/Displayall` -> returns `200` with JSON array.
  - `POST /gym/Add` -> test adding a record with JSON payload (no `id`).
  - `DELETE /gym/Delete/{id}` -> test deleting by ID.

### 2. Manual End-to-End User Flow via Frontend
1. **Connect & Status**:
   - Open `index.html`. Observe the **Backend Online (Port 8081)** badge in the navbar turn green.
2. **Add Record Flow**:
   - Click **Add Equipment** (or use the testing preset button *"Fill Valid Sample"*).
   - Verify that **NO ID field** exists in the form.
   - Click **Add Equipment** submit button.
   - Observe the success toast notification displaying the auto-generated database ID.
3. **Display Records Flow**:
   - The view automatically displays the **Equipment List** table.
   - Confirm that the new record is present with formatted currency, operational status badge, and auto-generated ID.
   - Check real-time filter by searching or selecting "Operational Only".
4. **Delete Record Flow**:
   - Click the red trash icon on the newly created record.
   - A Bootstrap confirmation modal appears showing the record ID and name.
   - Click **Delete Record** &rarr; record is deleted via `DELETE /gym/Delete/{id}` and removed from the table.
5. **Validation Testing**:
   - Submit empty form &rarr; clear red validation errors appear for required fields.
   - Enter negative purchase cost (e.g., `-50.00`) &rarr; triggers *"Purchase cost must be greater than zero"*.
